# CMU Library Explorer: the website

TypeScript + plain CSS, built with esbuild into static files. No PHP, no server of our own:
**Vercel** hosts the files, **Supabase** is the database, the login and the file storage.
The game lives at `/play/` on the same address, so one account works in both places.

## Folder map

| Path | What it is |
| --- | --- |
| `src/pages/*.html` | One file per page. `"shell":"landing"` pages (landing, about, login...) get the public header; `"shell":"app"` pages (catalog, panel, settings...) get the sidebar app. Menus come from `src/data/nav.json`. |
| `src/styles/` | All the look. `tokens.css` (sizes, motion), `themes.css` (Library Blue / Cozy Cream / Night colours, picked in Settings), `pixel.css` (the one card style), `components/`, `pages/`. |
| `src/ts/core/` | Session, Supabase client, toasts, modals, theme, animations. |
| `src/ts/api/` | Every database call, grouped by topic (auth, catalog, loans, content, staff). |
| `src/ts/ui/` | Reusable markup (book cover, cards, pagination, form fields). |
| `src/ts/pages/` | One script per page. `src/ts/panel/` holds the staff panel sections. |
| `public/` | Fonts, sprites, icons, covers, and the game build (`public/play`). |
| `../supabase/*.sql` | The database. |

Rules the code follows: colours and sizes only come from CSS variables (a new theme is one block in
`themes.css`), pages never talk to the database directly (only through `ts/api`), and text from users is
escaped by the `html` template helper.

## 1. Supabase (once)

1. Create a project at supabase.com.
2. SQL editor, run in this order: `supabase/site.sql`, then `supabase/books.sql`, then `supabase/site_seed.sql`.
3. Authentication > URL configuration: set **Site URL** to your Vercel address and add
   `https://YOUR-SITE/login` and `https://YOUR-SITE/reset` to **Redirect URLs**.
4. Authentication > Providers > Email: for school use you may turn off "Confirm email" so people can play at once.
5. Make the first admin. Register on the site, then in the SQL editor:

```sql
update public.profiles set role = 'admin' where lower(username) = lower('YourUsername');
```

6. Live availability: Supabase Realtime must be on (Project settings > Realtime, leave "Allow public access" enabled).
   The database then announces every reserve, borrow and return on the public `library-stock` channel (counts only),
   and both the website and the game update their book cards at once. Without Realtime everything still works,
   it just refreshes on the next page load.

Admins make staff in the panel (Staff > Add staff; the person registers first) and give them permissions. Students can never make themselves staff.

## 2. Vercel

- Import the repository, set **Root Directory** to `site`.
- Build command `npm run build`, output directory `dist` (also in `vercel.json`).
- Environment variables: `SUPABASE_URL` and `SUPABASE_ANON_KEY` (the public anon key, never the service key).

## Email (borrow emails with QR, reset codes, notices)

Every email uses the library design (crest logo, library blue and gold, status pill, book card, QR frame). They are built in
`api/_mail.mjs` (borrow, return, notices) and `tools/make-auth-emails.mjs` (Supabase sign-in emails). No n8n is needed for any of them.

- **Gmail sender** (borrow emails and notices): in Vercel add `GMAIL_USER` and `GMAIL_APP_PASSWORD` (a Google *App password*), and `SITE_URL`
  (for example `https://library.example.com`, used in the QR link). Optional `LIBRARY_FROM_NAME`.
- **Borrow emails**: reserving a book emails the student the book details and a QR code; the staff scan confirms the pickup and emails a
  confirmation with the due date; return, declined and cancelled emails follow. A student has ONE QR code for all their books: the email lists every reserved book under that one QR and staff confirm them all with a single scan.
  The QR is generated by the server for every loan, so it works with or without n8n. Each email is sent once per loan.
- **Loans made in the game** are emailed too once the database hook is on: as admin open **Settings > Loan emails with QR codes**, press
  **Generate**, **Save**. (Needs the `pg_net` extension, created by `supabase/site.sql`. Without it, only loans made on the website send emails.)
- **Staff scan desk**: **Scan pickup** in the sidebar (`/pickup`). Camera scanning works on https (Chrome, Edge, Safari, phones); typing the code always works.
- **Supabase sign-in emails** (6-digit code, confirm, invite...): run `node tools/make-auth-emails.mjs`, then paste each file from
  `../supabase/email-templates/` into Authentication > Emails (HTML body, and the `.subject.txt` as the subject). Authentication > SMTP Settings: use
  the library's Gmail (host smtp.gmail.com, port 465, the Gmail address and an app password). Set the OTP expiry to 900 seconds.
- **Sign-up and reset use a 6-digit code, not a link.** Mail apps open links to scan them, which uses the link up (`otp_expired`). The templates only show the code; the Join page asks for it.
- Without Gmail the buttons say email is not set up yet; everything else keeps working.
- **Email not arriving?** As admin open **Settings > Loan emails with QR codes > Send me a test email**. It says exactly what is missing (a Vercel variable, a wrong Gmail
  app password, or `supabase/site.sql` not re-run) and sends a sample QR email to your account.
- **Links in Supabase emails open `localhost:3000`?** Supabase > Authentication > URL configuration: set **Site URL** to your Vercel address (not localhost) and add
  `https://YOUR-SITE/login` and `https://YOUR-SITE/reset` to Redirect URLs. `otp_expired` means the link was old or already opened once; use Forgot password for a new code.

## Deploy the website first (the game can come later)

The site builds and runs without the game. The **Game** page checks whether `/play/` exists and shows
"Coming soon" until you publish it, so you can deploy now and test everything else:

1. Run `npm test` locally (typecheck, database rules, login lock, assistant and its tools, emails, CSS audit, broken-link check).
2. Push, import into Vercel (Root Directory `site`), add `SUPABASE_URL` and `SUPABASE_ANON_KEY`, deploy.
3. Add the Supabase redirect URLs (step 3 above), register, make yourself admin (step 5).
4. Click through as student and as admin. Things to try: register, sign in, wrong password 3 times (30 s lock),
   request a book, approve it in Circulation, post an announcement, change theme in Settings, open the assistant.
5. In **Site settings** set the game status to *Open* only when the game is published.
6. Optional: connect the AI assistant (n8n), see `ASSISTANT_PROMPT.md`.

## 3. The game inside the site

```bash
python tools/build_web.py "C:/path/to/Godot_v4.6.1-stable_win64_console.exe" --site
```

This exports the web game into `site/public/play`, which Vercel then serves at `/play/`. The game reads the
website's saved login, so the username from sign-up is automatically the player's name. Players who are not
signed in are sent to the login page and brought back. After login the game opens inside the **Game** page of the website
(press *Enter the game*), with the player's Student, Staff or Admin label shown above their head. The desktop game shows an email and password box instead.

## Working on it

```bash
npm install
npm run dev        # http://localhost:5173, rebuilds on every save
npm test           # typecheck + the SQL rules test (runs the real SQL in an embedded Postgres)
```

No Supabase project yet? Try everything with the built-in fake backend:

```bash
node tests/mock-server.mjs                                              # terminal 1
SUPABASE_URL=http://localhost:54321 SUPABASE_ANON_KEY=mock npm run dev  # terminal 2
```

Sign in with `student@cmu.test` or `admin@cmu.test`, password `pass1234`.
